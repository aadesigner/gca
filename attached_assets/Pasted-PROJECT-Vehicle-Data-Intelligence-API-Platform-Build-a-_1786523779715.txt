PROJECT: Vehicle Data Intelligence & API Platform

Build a production-oriented web application using Node.js/TypeScript, PostgreSQL, React/Next.js or another modern React frontend, and a clean REST JSON API.

The application is an internal vehicle-data aggregation platform. It collects historical vehicle information from multiple third-party auction/marketplace sources, stores every historical observation without overwriting previous observations, normalizes the data around VINs, and exposes the resulting data through a token-authenticated API.

IMPORTANT:
This is NOT primarily a live marketplace.
The core database is a historical vehicle-data database.
Live inventory/feed providers are a separate subsystem.

==================================================
1. CORE CONCEPT
==================================================

A single VIN can appear on multiple websites and multiple times over its lifetime.

Example:

VIN X
- 2019: appears on Encar with 80,000 km
- 2020: appears on another auction with 91,000 km
- 2021: appears at IAAI after an accident
- 2022: appears on Copart with 105,000 km
- 2024: appears on another marketplace

NEVER overwrite historical information.

Instead, store individual observations/events with:
- VIN
- provider/source
- source listing ID
- source URL
- date/time observed
- listing date if available
- mileage
- sale/auction price
- currency
- accident/damage information
- status
- make
- model
- year
- trim
- engine
- fuel
- transmission
- drivetrain
- location
- photos
- seller information when legally/technically appropriate
- all other available vehicle fields
- raw source response/data
- normalized data

The system should be able to reconstruct the vehicle's history chronologically.

==================================================
7. APPEND-ONLY HISTORY
==================================================

This is extremely important.

If the same VIN is discovered again:

DO NOT replace the old record.

Instead:

Vehicle:
    VIN = X

Observations:

2019-04-10
provider = encar
mileage = 72,000
price = $18,000

2020-02-14
provider = another_provider
mileage = 84,000
price = $16,500

2021-08-03
provider = copart
mileage = 95,000
damage = front end

The API should be able to return the chronological history.

Deduplicate only identical observations.

Use a deterministic fingerprint/hash of:
- VIN
- provider
- source listing ID
- event date
- relevant observation fields

If a listing changes, preserve the previous observation and create the new observation when appropriate.

==================================================
8. RAW DATA
==================================================

Always retain the original source data whenever legally and technically appropriate.

Store:
- raw HTML/JSON where permitted
- request URL
- collection timestamp
- provider
- parser version
- checksum

Raw data is important because parsers will change.

Allow reprocessing old raw data with a newer parser without recollecting the source.

24. VIN MATCHING
==================================================

Normalize VIN:

- uppercase
- remove spaces
- validate length
- validate VIN format where applicable

Do not automatically merge vehicles solely because make/model/year match.

If VIN is unavailable, store the listing as an unresolved vehicle/listing and allow later VIN resolution.

36. IMPORTANT LEGAL/TECHNICAL CONSTRAINT
==================================================

Only collect and use data in ways permitted by the relevant source's terms, applicable law, robots/access rules, and any licenses or API agreements.

The architecture must support official APIs and permitted data feeds as first-class provider mechanisms.

Do not implement:
- CAPTCHA bypassing
- authentication bypasses
